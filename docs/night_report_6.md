- **入力構築**（変更前）: `<s>` 指示 `</s><s>` 選択肢+`<mask>`… `</s><s>` state `</s>`。

- **mask 位置**: 固定オフセットではなく、系列を組み立てながら `<mask>` を置いた位置を記録する方式。
  choice / score / bool で共通。修正は不要でした。`state_first` では質問ブロックの開始位置を足して求め、
  返す前に全位置が `<mask>` であることを検査します。
- **切り詰め**: 上限 1024、state の末尾側を切る。**両方の順で、全データ（学習 67,394 行、val、
  held-out 2 種、長文 val、M4 用 70 行）の切り詰めは 0 件**。最大 joint 長 730。
- **テスト**: (a) 既定順は変更前の出力とバイト単位で一致（サンプル 9 件と collate 後のテンソル、
  さらに 4 ファイル全行の sha256）、(b) トークン多重集合の差 0 行、(c) mask 位置の不一致 0 行、
  (d) 保存→再読込で `state_first` を保持、キー無しの旧チェックポイントは `question_first`、
  順序違いのバッチは拒否、(e) 切り詰め 0。
- **M4 の選定**: day3 の S 属性で定義が state の冒頭で決まるのは `includes_greeting` だけ。
  held-out セットには無いため、`data/docs_all_v5.jsonl` の val 分割の文書から学習と同じ棄却規則で

## 5. 予想と違ったこと

1. **mask を state の末尾に寄せても、`ends_with_question` は上がりませんでした**（平均 0.661 → 0.652）。
   通常の長さの state では、距離は位置依存属性の弱さを説明しません。
2. **それなのに長い state では明確に良くなりました**（参考: 400–599 帯 AUROC 平均 0.868 → 0.901、
   600–799 帯 0.704 → 0.782 で n=33、M2 帯の `ends_with_question` acc 0.560 → 0.671 で n=72）。
   3 シードとも v0.1 の最大を上回っています。前回の報告にあった「長文での劣化」は、`state_first` では
   ほぼ見えなくなりました。
3. **冒頭で決まる M4 は予測と逆に上がりました**（0.543 → 0.624、n=70）。ただし seed 2 は v0.1 と同じ
   0.5143 で、シード間の差が大きい。
4. **採用候補は M2 だけで決まっています。** M1 の平均は v0.1 の平均より低く（0.8826 対 0.8876）、
   最小値との差は 0.0008 しかありません。`implies_declining` は平均 0.799 → 0.722 と下がりました。

## 6. 判断していただきたいこと

1. **採用候補への対応**。規則上は該当ですが、改善は長文の 210 行（M2）に集中しており、
   held-out 全体（M1）は v0.1 の平均を下回っています。bench を 1 回だけ回して決めるか、
   `question_first` を公開版として維持するか。bench の実行はご判断にお任せします。
2. **次の実験の候補: v0.1 の長文劣化を、学習と評価の系列長の不一致として切り分ける実験。**
   学習データは全系列 443 トークン以下、評価の長文は最長 730 トークンです。
   前提: 窓 128 では sliding 層の相対距離は評価時も ±64 に収まり、学習時と同じ範囲です。
   したがって不一致が効くとすれば **global 層側**（微調整中に一度も見ていない 443 超の相対距離）です。
   今回 `state_first` で長文が良くなったことは、この切り分けの前にもう一つ説明を増やしています
   （mask の直前に state の末尾が来る並びでは、長文でも mask 近くの内容は学習時と同じ距離にある）。
   **どちらが効いているかはまだ測っていません。**
3. M4 は n = 70 で、1 件が 0.014 に当たります。冒頭依存の属性を判定に使い続けるなら、
   val 文書を増やすかどうか。
