# v0.2 の速度（1 件あたりの時間とスループット）

T0 = 2026-09-27 23:16:01（night_19）。**§1 は計測の前に書いて commit しています。** 結果は §2 以降に追記します。

## 1. 計測条件（`scripts/latency_v02.py`）

- **モデル**: v0.2（`runs/release_candidate/model.pt`）。`sokudan.load(..., device=...)` で読み込みます。温度は当てません。
- **1 件あたりの時間**:
  - `agent.predict({"body": state}, bench_questions())` を、`bench_ja` の 300 件に 1 件ずつ 1 回呼びます（3 問 = choice 4 択、score 3 水準、bool）。
  - 最初の 20 件は計測しないウォームアップです。その後 300 件を先頭から計ります。
  - `time.perf_counter` で `predict` の呼び出しを挟みます（戻り値はホストの数値なので、GPU の処理は終わっています）。
  - 中央値と p95 を出します（平均、最小、最大も記録）。
- **スループット**:
  - 同じ 900 問（300 件 × 3 問）を、問いの型ごとに 32 行ずつ、`predict` と同じ前向きの経路（JointCollator、fp32、autocast なし）に流します。
  - 計測しない 1 巡のあとに 1 巡を計り、問 / 秒を出します（CUDA を同期）。
- **環境**:
  - GPU: NVIDIA GeForce RTX 5090。
  - CPU: Intel Core Ultra 9 285K（24 コア / 24 スレッド）。`torch.get_num_threads()` の値を記録します（既定のまま）。
  - 学習や他の GPU の処理が動いていないときに測ります。
- **数えないもの**: ラベルは読まず、精度は計算しません（`bench` の評価ではない）。
- **注意**: state は問いごとにエンコードし直します（v0.1 から同じ構造）。1 件 3 問の時間には、3 回分のエンコードが入ります。
