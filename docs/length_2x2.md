# 長さ × 入力順の 2×2 実験（事前登録 (1)）

**研究の問い**: v0.1 の長文劣化（M2）の原因は、次のどちらか。

- **長さの不一致**: 学習データは全系列 443 トークン以下、評価には 730 トークンまである
- **位置**: `question_first` では、state の末尾が mask から遠い

前回（`docs/input_order.md`）、`state_first` で M2 は 0.8451 → 0.8851 に改善しました。
今回は長い学習データを足し、**入力順 {question_first, state_first} × 学習データの長さ
{short（現行）, long（長文を追加）}** の 2×2 で切り分けます。

| 条件 | 入力順 | 学習データ | チェックポイント |
|---|---|---|---|
| **qf-short**（= v0.1） | question_first | `data/train_v2b.jsonl` | `runs/v01_seed{0,1,2}`（既存） |
| **sf-short**（= io_sf） | state_first | `data/train_v2b.jsonl` | `runs/io_sf_seed{0,1,2}`（既存） |
| **qf-long** | question_first | train_v2b + 長文 | 新規 3 シード |
| **sf-long** | state_first | train_v2b + 長文 | 新規 3 シード |

**§0〜§7 は、生成した長文にも新しいモデルの数字にも触れる前に書き、本生成の前に commit しています。
以後動かしません。** 生成後のデータの確定は「事前登録 (2)」として追記します（学習前に commit）。

## 6. 指標と判定規則（Phase 5 で機械的に当てはめる）

評価はすべて `scripts/eval_local_attention.py`（前回までと同じ定義、held-out / val のみ）。

- **M1**: held-out bool AUROC（frozen、n = 9,850）
- **M2**: 400–799 帯の held-out bool AUROC（n = 210、既存定義）
- **M5**: `implies_declining` の held-out AUROC（frozen、n = 818）
- **ガードレール**: choice acc、score RPS（小さいほど良い）、score acc、bool acc（`val_v2`）
- 参考のみ: M3（`ends_with_question` acc）、M4（`includes_greeting` acc）、400–599 帯、600–799 帯

**差の有無**: 条件 A と B の M2 の 3 シード平均の差 |mean_A − mean_B| が、max(range_A, range_B)（range = 3 シードの
max − min）を**超えたら「差あり」**（方向は平均の大小）。超えなければ「差なし」。
「X > Y が差あり」は「差あり、かつ mean_X > mean_Y」を意味する。

**結果の型**（上から順に最初に当てはまるもの。A〜C が同時に成り立つ場合は、その旨も記録する）

- **型 A「長さが主因」**: qf-long > qf-short が差あり、かつ（qf-long と sf-short が差なし、または qf-long > sf-short）
- **型 B「位置が主因」**: qf-long と qf-short が差なし、かつ sf-short > qf-short が差あり
- **型 C「両方効く」**: qf-long > qf-short が差あり、かつ sf-long > qf-long と sf-long > sf-short がどちらも差あり
- **型 D「その他」**: どれにも当てはまらない。解釈はユーザーに委ねる

**最終候補**（4 条件すべてに適用）

- 足切り（すべて満たす）: M1 平均 ≥ **0.881718**、M5 平均 ≥ **0.772710**、choice acc 平均 ≥ **0.700911**、
  score RPS 平均 ≤ **0.187460**、score acc 平均 ≥ **0.512931**、bool acc 平均 ≥ **0.929407**（すべて v0.1 3 シードの最悪値）。
- 足切りを通った条件のうち M2 平均が最大の条件を C* とする。足切りを通った条件のうち C* と M2 が「差なし」のものがあれば、
  C* を含むその集合から**単純な方**を選ぶ。単純さの順は、まず入力順（question_first を優先）、次に長さ（short を優先）:
  **qf-short > qf-long > sf-short > sf-long**。
- 足切りを通るのが qf-short（v0.1）だけなら v0.1 を維持する。
- どの結果でも bench は実行しない。

判定は `scripts/l2x2_gate.py`（学習前に作成して commit する）で、`runs/io/eval_v01.json`、
`runs/io/eval_seed0.json`、`runs/io/eval_seed12.json` と新しい評価出力の倍精度値から行う。

## 7. Phase 6（条件付きの追加実験。上から順に、条件を満たすものを 1 つだけ）

各項目は「実測の学習時間 × 本数 × 1.3 + 評価時間」が終了処理の開始（T0 + 7:30 = 06:08）までに収まる場合だけ始め、
判定規則は開始前にここへ追記して commit する。

1. 最終候補が long を含む場合: データ量の対照（replace 条件）。v0.1 の学習データから長文と同数の短文（文書単位）を固定シードで
   抜き、長文で置き換えて総文書数を v0.1 と同じにし、最終候補と同じ入力順で 3 シード。replace の M2 平均が short 側の同順条件の
   最大値を超えれば「長さの効果はデータ量と独立」、超えなければ「データ量との交絡を否定できない」。
2. 型 B、または最終候補が sf-short の場合: `implies_declining` の誤り分析（学習なし）。qf-short と sf-short の 3 シードで
   「3 シードとも正解 → 3 シードとも誤り」に変わった事例について、断りの表現が state の前半・後半のどちらにあるかを数える。
   位置の規則は分析前に書く。結論は強く言わない。
3. データなし分岐（Phase 1 か 2 のゲートで止まった場合）: 2 の誤り分析だけ。
