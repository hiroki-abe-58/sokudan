# 「その他」を足すと崩れるか（実使用報告の再現、CPU）

## 0. 背景

- X で、sokudan を勘定科目の候補提示に使っている利用者から、報告がありました。
  - 内容は、「その他」の選択肢を足すと結果が崩れる、というものです。
  - 本人によれば、起きたのは勘定科目ではなく、一般的な文字列で検証したときです。
  - スレッド: https://x.com/t28k2/status/2104322335671206306
- 先に、こちらで作った小さなセットで現象が出るかを見ます。
- `bench_ja` の部署ルーティング（4 択、「その他: 上記以外」つき）で、v0.2 の choice acc は 0.880 です。
  - 違いがあるとすれば、選択肢が多い（K = 6〜11）ときか、「その他」に当たる state が実際に混ざるときか、その両方です。
- 実行は CPU だけ（`CUDA_VISIBLE_DEVICES=""`）です。学習はしていません。

## 1. セット

`docs/probe_catch_all/set.json`。

- **勘定科目 10 項目**: 旅費交通費、通信費、消耗品費、事務用品費、会議費、交際費、広告宣伝費、水道光熱費、新聞図書費、修繕費。各項目に 1 行の説明を付けています。
- **state**: 経費の 1〜2 文を、項目ごとに 8 件（計 80 件）。
- **どの項目にも当たらない state が 10 件**: 見舞金、クラウド会計ソフトの利用料、税理士の顧問料、家賃、健康診断、火災保険料、振込手数料、商工会議所の年会費、収入印紙、アルバイトの給与。本来の科目は `true_account` に書いています。
- **near-miss の対**: 消耗品費 / 事務用品費、会議費 / 交際費。どちらとも読める state を意図して入れ、`near_miss` の印を付けました。
- **「迷い」**: 書いた本人がラベルに迷った state です。`uncertain` の印と理由を付けて残しました（7 件）。
- **著者は 1 人です。** state、説明文、ラベル、印は、すべて Claude Code（Opus 5.5）が書きました。LLM で生成したデータではありませんが、第三者による確認はしていません。

## 2. 条件

| 条件 | 選択肢 | K | 評価する state | 正解 |
|---|---|---|---|---|
| A | 10 項目（説明つき）、その他なし | 10 | 80（該当なしの 10 件は除く） | その項目 |
| B | 10 項目 + 「その他: 上記以外」 | 11 | 90 | 該当なしは その他 |
| C | 5 項目（消耗品費、事務用品費、会議費、交際費、通信費）+ その他 | 6 | 90 | 5 項目の 40 件はその項目。残り 5 項目の 40 件と該当なしの 10 件は その他 |
| D | B と同じ、説明文なし（ラベルだけ） | 11 | 90 | B と同じ |

- **順序**: 各条件で、選択肢の順序をランダムに 20 通り使います。順序 j は `random.Random(20260928 + j)` で決め、どの条件でも同じ seed です（B と D は同じ並べ替え）。「その他」も並べ替えの対象です。
- **質問文**: 「この経費はどの勘定科目に当たるか」。
- **sokudan**: `GeneLab/sokudan-ja-310m`（v0.2.1、HF main）。state は文字列で渡します。
  - 較正は既定のまま（bool だけ）で、choice の確率は生の値です。
  - 確率は `predict` の出力（小数 4 桁）です。argmax が引き分けた決定の数は記録します。
- **参考: laya-multilingual**（`convaiinnovations/laya-multilingual`、CPU）。state は `{"body": state}` で渡します（`docs/baseline_ja.md` のベースラインと同じ形）。
- **既存の道具について**: `sokudan probe-position` と presentation checks は score の 3 水準・bench の state 用で、この条件にはそのまま使えません。そのため、同じ定義（第 1 スロット率 = 選ばれた選択肢が提示順の先頭だった割合、順序に依らなければ 1/K）を `scripts/probe_catch_all.py` に書きました（`python scripts/probe_catch_all.py run --model sokudan:GeneLab/sokudan-ja-310m --name <名前>`。入力は `docs/probe_catch_all/set.json`、出力先は `--out`、既定は `./probe_catch_all_out/`）。

## 3. 見るものと「崩壊」の判定（実行前に commit）

**指標**:

- 正解率: 20 通りの順序ごとの正解率の平均、最小、最大。「迷い」を除いた値も出します。
- 「その他」に落ちる割合: 正解が「その他」の state と、そうでない state に分けます。C では「その他」の正解を、該当なしの 10 件と、残り 5 項目の 40 件にさらに分けます。
- P(その他) の分布: 平均、中央値、90% 点、0.5 以上の割合。
- 第 1 スロット率、最終スロット率。
- 入れ替わり率: 20 通りのあいだで答えが変わった state の割合。あわせて、最頻の答えの占有率の平均。
- 平坦さ: 最大確率の平均と、正規化エントロピーの平均。
- near-miss の対の混同行列（決定数 = state 数 × 20）。
- 「その他」の位置別: その他が最後にある順序と、それ以外の順序での正解率。

**「崩壊」の判定**（sokudan について。数字を見る前に決めたもの）:

1. **崩壊の再現**: 条件 B で、その他以外が正解の 80 件の正解率（順序平均）が、条件 A の同じ 80 件より **0.10 以上低い**。
2. **型 (a)「その他に確率が集まる」**: 1 が成り立ち、かつ、B でその他以外が正解の決定のうち「その他」を選んだ割合が、減少分（A − B）の半分以上。
3. **型 (b)「全体が平坦になり、答えが順序で入れ替わる」**: 1 が成り立ち、かつ、B の入れ替わり率が A より 0.10 以上高いか、B の最大確率の平均が A より 0.10 以上低い。
4. (a) と (b) は両方成り立つこともあります。1 が成り立って、どちらでもなければ「その他の形」として中身を書きます。
5. **C と D も同じ規則で見ます。**
   - C: 5 項目の 40 件の正解率を、A の同じ 40 件と比べます。あわせて、正解がその他の 50 件で「その他」を選ぶ割合を記録します（判定はしない）。
   - D: B と同じく、80 件を A と比べます。
6. **laya-multilingual は参考値で、判定には使いません。**

## 4. 結果

- **実行**: 2026-09-28、CPU（`CUDA_VISIBLE_DEVICES=""`）。
  - sokudan は 16:23:58 開始で、A 157 s、B 186 s、C 108 s、D 46 s でした。
  - laya-multilingual は 16:32:23 開始で、A 115 s、B 133 s、C 89 s、D 38 s でした。
- **生の確率と集計**は、`scripts/probe_catch_all.py` の `run` と `report` で作り直せます（出力先は `--out`、既定は `./probe_catch_all_out/`）。この文書の数字の元になった出力ファイルは公開していません。
- argmax の引き分けは、事前登録の実行では 0 件でした。

### 4.1 sokudan: 4 条件（事前登録の実行、ランダムな 20 通り）

| 条件 | K | 件数 | 正解率 平均 [最小, 最大] | 「迷い」を除く | その他以外が正解の state の正解率 | 「その他」落ち率（正解 ≠ その他） | 「その他」を選んだ率（正解 = その他） | 入れ替わり率 | 第 1 スロット率（1/K） | 最大確率の平均 |
|---|---|---|---|---|---|---|---|---|---|---|
| A | 10 | 80 | 0.840 [0.738, 0.925] | 0.846 | 0.840 | — | — | 0.388 | 0.092（0.100） | 0.856 |
| B | 11 | 90 | 0.790 [0.744, 0.833] | 0.800 | **0.852** | 0.002 | **0.295** | 0.411 | 0.076（0.091） | 0.801 |
| C | 6 | 90 | 0.561 [0.400, 0.756] | 0.562 | **0.785**（A の同じ 40 件: 0.723） | 0.018 | **0.381** | 0.722 | 0.137（0.167） | 0.732 |
| D | 11 | 90 | 0.783 [0.733, 0.811] | 0.789 | **0.843** | 0.001 | **0.300** | 0.400 | 0.074（0.091） | 0.822 |

- C の「その他」を選んだ率の内訳は、該当なしの 10 件が 0.425、残り 5 項目の 40 件が 0.370 です。
- **入れ替わり率を、正解が「その他」の state だけで見ると高くなります**: B 0.90、C 0.92、D 0.70。その他以外が正解の state では、B 0.35、C 0.475、D 0.36 です。

**判定（§3 の規則）**:

1. 崩壊の再現（A との差 −0.10 以下）は、どの条件でも成り立ちませんでした。**事前に決めた意味での「崩壊」は、このセットでは出ませんでした。**
   - B: 0.852 − 0.840 = **+0.012**。
   - D: 0.843 − 0.840 = **+0.003**。
   - C（5 項目の 40 件）: 0.785 − 0.723 = **+0.063**。
2. 型 (a)・型 (b) は、規則 1 が成り立つときだけ判定するものです。判定は行っていません。
   - 記述として: その他以外が正解の state では、P(その他) はほとんど上がっていません（B の平均 0.027、0.5 以上は 0%）。
   - 記述として: B の平坦さの変化は A に対して、最大確率 −0.055、入れ替わり率 +0.023 で、どちらも規則の 0.10 に届きません。

### 4.2 代わりに見えたこと: 「その他」がほとんど選ばれない

**P(その他) の分布**（決定ごと、sokudan）:

| 条件 | 対象 | 平均 | 中央値 | 90% 点 | 0.5 以上 |
|---|---|---|---|---|---|
| B | 正解 ≠ その他（80 件） | 0.027 | 0.012 | 0.068 | 0.000 |
| B | 正解 = その他（10 件） | 0.183 | 0.170 | 0.332 | 0.000 |
| C | 正解 ≠ その他（40 件） | 0.053 | 0.010 | 0.171 | 0.009 |
| C | 正解 = その他（50 件） | 0.321 | 0.300 | 0.630 | 0.241 |
| D | 正解 ≠ その他（80 件） | 0.023 | 0.012 | 0.053 | 0.001 |
| D | 正解 = その他（10 件） | 0.214 | 0.190 | 0.457 | 0.050 |

- 「崩壊」の候補 (a)「その他に確率が集まる」は、**逆向き**でした。その他に当たる state でも P(その他) は上がりきらず、argmax はリストの中の項目に行きます。
- (b)「平坦になって順序で入れ替わる」は、**その他に当たる state に限って**見えます。入れ替わり率は 0.70〜0.92 です。
- **順位は取れています。** P(その他) で「正解がその他か」を分ける AUROC は、B 0.942、C 0.912 です（事後の計算）。
  - 「その他の項目のうち最大の確率が低い」ことでも分けられ、AUROC は B 0.877、C 0.869 です。
  - その他の state での最大確率の平均は、B 0.473 / その他以外 0.837 です。
  - **信号はあるのに、argmax の閾値に届いていません。** bool の「順位は取れているが閾値がずれる」（README の Limits）と同じ形です。

**その他に当たる state がどこへ行くか**（C、決定数、各 160 または 200）:

| 本来の科目 | ランダムな順序: その他 / 最も多い行き先 | その他を最後に固定: その他 / 最も多い行き先 |
|---|---|---|
| 旅費交通費 | 81 / 通信費 53 | 29 / 通信費 72 |
| 広告宣伝費 | 36 / 交際費 68 | 19 / 交際費 75 |
| 水道光熱費 | 57 / 通信費 87 | 5 / 通信費 131 |
| 新聞図書費 | 80 / 通信費 31 | 77 / 通信費 49 |
| 修繕費 | 42 / 消耗品費 114 | 23 / 消耗品費 135 |
| 該当なし 10 件 | 85 / 通信費 63 | 54 / 通信費 87 |

- リストにない科目の state は、**意味の近い、リストにある項目**に行きます。
  - 水道光熱費 → 通信費（どちらも月額の料金）。
  - 修繕費 → 消耗品費。
  - 広告宣伝費 → 交際費。
- 該当なしの 10 件も同じです（B、その他を最後に固定）。
  - 家賃 → 水道光熱費 20/20、収入印紙 → 通信費 20/20、見舞金 → 交際費 19/20。
- 「その他」になりやすいのは、税理士の顧問料、商工会議所の年会費、アルバイトの給与でした。どの項目とも語が重ならない state です。

### 4.3 「その他」の位置（事後の追加、判定には使わない）

事前登録の 20 通りでは、「その他」が最後になった順序は B と D で 1 通り、C で 3 通りしかありませんでした。

**P(その他 | 正解 = その他) を、その他の位置別に見ます**（sokudan、事前登録の実行から）:

## 5. 読み取れたこと

1. **事前に決めた意味の「崩壊」（その他を足すと、リストの項目に当たる state の正解率が落ちる）は、このセットでは出ませんでした。**
   - B、C、D のどれでも、リストの項目に当たる state の正解率は A と同じか、少し高い値でした。
   - その他以外が正解の state で「その他」に落ちる率は、0.2% 以下（C は 1.8%）です。
2. **見えたのは逆の問題です。「その他」がほとんど選ばれません。**
   - 該当なしの state でも、その他が選ばれるのは 30%（B）です。その他を最後に置くと 16%（B）、6%（D）まで下がります。
   - 選ばれなかった state は、意味の近いリストの項目に入ります。
   - C のように、リストにない科目が半分を占める設定では、全体の正解率は 0.56（ランダムな順序）/ 0.47（その他が最後）です。**実使用者が「崩壊」と呼んだものがこれである可能性はあります。ただし、確認はしていません。**
3. **「その他」の state では、答えが順序で入れ替わります**（入れ替わり率 0.70〜0.92）。確率の低い候補どうしの争いになっているためです。
4. **P(その他) の順位は取れています**（AUROC 0.91〜0.94）。argmax ではなく、P(その他) やリストの項目の最大確率に閾値を置けば、「その他」を拾える見込みがあります。これは事後の計算で、閾値の決め方と効果は測っていません。
5. **「その他」は、先頭と最後の位置で選ばれにくくなります。** 最後に置くふつうの使い方が、いちばん不利な位置の 1 つでした。
6. **near-miss では、消耗品費 → 事務用品費と、交際費（飲食） → 会議費への片寄りがあります。** 「その他」とは別の弱点です。

## 6. 限界

- セットは 90 件で、著者は 1 人です。ラベルも著者が付けました。「迷い」7 件を除いた正解率も出していますが、ほとんど変わりません。
- **実使用者の検証（一般的な文字列）とは、データも選択肢も違います。** 同じ検査は、`scripts/probe_catch_all.py` と自分のセットで行えます（入力の形式は `docs/probe_catch_all/set.json` と同じ）。
- 4.2 の AUROC と、4.3 の「その他を最後に固定」の実行は、事後の追加です。判定には使っていません。
- 確率は `predict` の小数 4 桁です（引き分けは、事前登録の実行で 0、その他を最後に固定した D で 1）。
- 正解率は、`bench_ja` の choice acc（0.880）とは state も質問も違うので、並べて比べられません。
