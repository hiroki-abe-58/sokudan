## 1. 基準と作るもの

- **基準**: v0.1 の 8 本（`runs/v01_seed0〜7`）の平均 μ と SD σ（不偏）。`docs/research_protocol.md` §1 の値を使います。
  - M1m: μ 0.831028 / σ 0.012591
  - M2: μ 0.837224 / σ 0.035855
  - M5: μ 0.781811 / σ 0.036470
  - M1: μ 0.882193 / σ 0.009724
  - ガードレールは `runs/nf/reread.json` の v0.1 の分布を使います。
- **作るもの**:
  - **E_qf8**: v0.1 の 8 本の予測確率の平均。
    - bool は P(true) を平均します。
    - choice は選択肢ごとの確率を平均します。
    - score は各水準の確率を平均します（モデルが出す水準の確率は、累積分布の差分です）。
  - **E_mix16**: v0.1 の 8 本と io_sf の 8 本（`runs/io_sf_seed0〜7`）の予測確率の平均。
    各モデルには、そのモデルが保存している入力順で入力を作ります（`load_checkpoint` が復元し、collator がそれに従う）。
  - **E_sf8**: io_sf の 8 本の平均（記述のみ）。
  - **Soup**: v0.1 の 8 本の全重み（ヘッドを含む）の単純平均。
    - 浮動小数の重みとバッファは平均し、整数のバッファは seed 0 のものを使います。
    - 事前に、ヘッドの初期値がシードで変わるかどうかをコードで確認して記録します。
- **予測確率の取り方**: 各チェックポイントについて、次の行の予測を事例ごとに保存します（`scripts/ens_collect.py`）。
  - frozen held-out の全行
  - M2 の長文 val（`docs_long_val` の held-out 行）
  - `val_v2` の全行（choice / score / bool）
  - 採点は `scripts/eval_local_attention.py` と同じ関数（`p_true`、`loop.evaluate` と同じバケット・同じ順序）です。
  - 単体のチェックポイントについては、保存済みの評価出力と一致することを確かめてから使います。

## 2. 指標と判定

- **指標**: M1m、M2、M5、M1、ガードレール（choice acc、score RPS、score acc、bool acc）。
  - 定義はこれまでと同じです。アンサンブルの確率に同じ指標関数（AUROC、`loop._metrics_for_group`）を当てます。
  - 各アンサンブルについて z_m = (値 − μ_m) / σ_m を出します。
- **蒸留に進む条件**: E_qf8 と E_mix16 のそれぞれについて判定します。
  {M1m, M2, M5} のうち **2 つ以上で z ≥ 1.0**、**かつ 3 つすべてで z ≥ 0** なら条件を満たします。
- **教師の選び方**:
  - 条件を満たす方のうち、{M1m, M2, M5} の z の合計が大きい方を教師にします。
  - 合計の差が 0.1 以内なら E_qf8 にします（単純な方を優先）。
- どちらも満たさない場合は蒸留しません。Phase 1b の後、終了処理に進みます。
- **Soup** は記述だけです。同じ条件を満たした場合は「soup 候補」と記録しますが、今夜はそれ以上何もしません。
- **注記**: アンサンブルは推論コストが 8〜16 倍になるので、製品の候補ではありません。天井を知るための参照値です。
