# 研究手順（2026-09-25 から、今後すべての実験に適用）

これまでの実験で分かったのは、3 シードの比較では出荷構成のシード間のばらつき（ノイズの床）に負けることです（`docs/noise_floor.md`）。
今後の実験は、この文書の規則に従います。この文書を変えるときは、変更の日付と理由を追記します。書き換えはしません。

## 1. 基準分布

- **出荷構成 v0.1**（batch 24、勾配累積 1、`question_first`、`--local-attention` なし、`data/train_v2b.jsonl`）の **seed 0〜7**。
  - チェックポイント: `runs/v01_seed<s>`
  - 評価出力: seed 0〜2 は `runs/io/eval_v01.json`、seed 3〜7 は `runs/nf/eval_v01_seed<s>.json`
- 基準分布の値（`runs/nf/reread.json`）:

|---|---|---|---|---|
| M1m | 0.831028 | 0.012591 | 0.816350 | 0.849339 |
| M1 | 0.882193 | 0.009724 | 0.862515 | 0.895507 |
| M2 | 0.837224 | 0.035855 | 0.762785 | 0.881415 |

## 2. 比較の単位

- 主張に使える比較は **1 条件 8 シード以上**です。8 本未満の結果は「予備」とし、判断には使いません。
- 比較相手も 8 本以上にします。基準分布（v0.1 の 8 本）は再学習せずに使います。

## 3. 検定

- **片側の正確置換検定**を使います。統計量は平均の差で、8 対 8 なら C(16, 8) = 12,870 通りをすべて列挙します
  （`scripts/seed8_stats.exact_permutation_p`）。
- 検定の**方向は事前登録で決めます**。
- 複数の検定には **Holm 補正**をかけ（`scripts/nf_test.holm`）、**α = 0.05** とします。
- 信頼区間はブートストラップ（条件内でシードを復元抽出、10,000 回、乱数シードを固定して記録）で出しますが、記述用です。

## 4. 健全性のゲート

- **M1m**（held-out の bool 属性ごとの AUROC の単純平均。n < 30 の属性は除く）をゲートに使います。
- M1（行をまとめた AUROC）は併記するだけにします。M1 の行の 71% は 2 属性（飽和した `requests_owner_change` と
  `ends_with_question`）が占めていて、健全性を表さないためです（`docs/noise_floor.md` §7）。

## 5. 破損停止

- 各条件の **seed 0** の M1m が「基準分布の最小値 − 2 × 基準分布の SD」を下回ったら、その条件を止めます。
- 現在の閾値は **0.791169**（= 0.816350 − 2 × 0.012591）です。

## 6. 勾配累積

- 勾配累積（batch 12 × 2 など）の経路で得た結果は、判断に使いません。
- 必要になったら、同じバッチ構成の 8 対 8 の対照実験をつけて検証します。
- メモリ不足になっても、勾配累積には切り替えません。止めて記録します。

## 8. GPU とテストの規則（2026-09-27 追記）

- **GPU を使う処理は、同時に 1 つだけにします**（学習、評価、GPU テスト、推論、外部モデルの実行を含む）。
  - 他のプロセスが VRAM を取ると、学習プロセスの上限（`--max-vram-fraction`）の外で合計が膨らみます（性能診断で 30.5 / 32.6 GB を観測）。
- **pytest は、既定で CUDA を隠します**（`tests/conftest.py` が `CUDA_VISIBLE_DEVICES=""` にする）。
  - GPU が必要なテストには `@pytest.mark.gpu` を付けます。
  - GPU テストは `SOKUDAN_TEST_GPU=1` のときだけ実行し、それ以外ではスキップします。
  - `SOKUDAN_TEST_GPU=1` で走らせるのは、学習や他の GPU ジョブが走っていないときだけです。
- 学習中にテストを流すときは、既定のまま（CUDA を隠したまま）走らせます。

## 9. 学習の数値に影響し得るコード変更（2026-09-27 追記）

- **学習の数値に影響し得るコード変更は、変更の前後で 8 対 8 以上の退行チェックを通し、基準分布を更新してから使います。**
- **変更履歴（2026-09-27）: ヘッド初期化の修正（f75e3f2）を戻しました。**
  - 事前登録した 16 対 16 の退行チェックで、修正後のコードの held-out M1m が低いと判定されたためです（p = 0.047、`docs/regression_check.md` §10）。
  - `scripts/train.py` の `build_model` は、再びシードを設定せずにモデルを作ります。スコアラの初期値はシードで決まりません。
  - **基準分布は old16 です**（旧コード＝戻した後のコードと同じ経路の v0.1 seed 0〜15）。M1m の平均は 0.8239（SD 0.0142）です。
  - §5 の破損の下限は、v0.1 の 8 本から決めた値（0.791169）のまま変えていません。

## 10. 基準分布と 1 本の再現性（2026-09-27 追記）

- **基準分布は 16 本以上、時期をまたいで取ります。**
  - 8 本の群どうしの差（旧コードの seed 0〜7 と 8〜15）が、コード変更の効果と同じ程度の大きさで出ました（`docs/regression_check.md` §10.3）。
- **同じコード・同じシードでも、GPU の非決定性で M5 が 0.1 動くことがあります**（`v01new_seed0` と `perf_a_seed0` で 0.720 と 0.826、`docs/perf_a.md` §4）。
  - このスタックでは、1 本の学習結果の再現性は保証できません。
  - 決定的モード（`use_deterministic_algorithms(True, warn_only=True)`）でも、memory-efficient attention の backward は決定的になりません。
- したがって、判断は常に分布（本数をそろえた群の比較）で行います。1 本の値や、同じシードでの再現を根拠にしません。
