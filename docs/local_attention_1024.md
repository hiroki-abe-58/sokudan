# local_attention 128 → 1024 の検証（事前登録）

v0.1 の 2 つの弱点が `modernbert-ja-310m` の `local_attention: 128` から来ているかを、
窓だけを 1024 に変えた 1 シードの学習で確かめます。

1. 位置依存の S 属性（`ends_with_question`）が弱い
2. 長い state で held-out bool の AUROC が落ちる（`docs/benchmarks.md` §6 の追試、400 トークン超）

**この節（§1〜§5）は新しいモデルの数字を見る前に書き、学習前に commit しています。以後
動かしません。** 結果は §6 以降に追記します。

## 1. 前提条件の確認（Phase 1、測定済み）

### 1.1 設定値（`sbintuitions/modernbert-ja-310m`、transformers 5.17.0）

| 項目 | 値 |
|---|---|
| `local_attention` | 128 |
| `global_attn_every_n_layers` | 3（25 層のうち full 9 層、sliding 16 層） |
| `sliding_window`（property） | 64 = `local_attention // 2` |
| RoPE base | sliding 10,000 / full 160,000（`rope_parameters`） |
| `max_position_embeddings` | 8192 |

### 1.2 実装の読み（`transformers/models/modernbert/modeling_modernbert.py`）

- `local_attention` は**窓の全幅**です。SDPA の sliding マスクは
  `abs(q_idx - kv_idx) <= config.sliding_window`（`sliding_window_bidirectional_overlay`）
  で、`sliding_window = local_attention // 2`。
- したがって **1024 は ±512** です。**全層が実質 global になるのは 513 トークン以下の系列だけ**で、
  それより長い系列では sliding 層は依然として局所的です。400–800 帯（M2）の一部はこの境界をまたぎます。
- sliding 層は RoPE base 10,000 のままです。窓を広げても sliding 層が global 層と同じに
  なるわけではありません（位置の扱いは事前学習時のまま、見える範囲だけが広がる）。
- 各 sliding 層の `ModernBertAttention` は構築時に `config.sliding_window + 1` を保持します
  （flash-attention 経路用）。SDPA マスクは forward 時に config から作られます。
  **上書きはモデル構築前に config に入れる必要があり**、`Backbone.load(local_attention=...)`
  の 1 箇所でそうしています。

### 1.3 変更点

- `Backbone.load(..., local_attention=None)` が唯一の上書き箇所。`None` は v0.1 と同じ経路。
- `scripts/train.py --local-attention N`（既定 None）。チェックポイントの config に
  **構築済みバックボーンの実際の値**を `local_attention` として保存。
- `scripts/eval_heldout.load_checkpoint` と `sokudan/predict.py` は保存値を復元。キーの無い
  既存チェックポイント（v0.1）は事前学習値 128 で読まれる。
- `sokudan/train/loop.py` の 50 ステップごとのログに経過秒とピーク VRAM を追加（ログのみ）。

### 1.4 テスト（`tests/test_local_attention.py`、全 6 件 pass、全体 603 件 pass）

| 項目 | 基準 | 実測 |
|---|---|---|
| (a) 60 トークン: 128 と 1024 の最終隠れ状態 | max 差 ≤ 1e-4 | **0.000e+00** |
| (b) 320 トークン: 同上 | max 差 > 5e-2 | max **26.1**、平均 0.283、320/320 トークンで 5e-2 超 |
| (c) 保存→`load_checkpoint` | config 1024、`sliding_window` 512、各 sliding 層 513、出力一致 | pass |
| (c') キーの無い旧チェックポイント | 128 で読まれる。明示の上書きは 1024 | pass |
| 既定経路 | 128 / 64 / 各 sliding 層 65 | pass |
| 上書きで重みは不変 | state_dict が完全一致 | pass |

## 2. 指標の定義（v0.1 の数字を見る前に確定）

すべて `scripts/eval_local_attention.py` で計算します。v0.1 の 3 シードも新しいモデルも同じスクリプトです。

  学習と同じ棄却規則）をプールし、state トークン数 400 以上 800 未満の行。
  **n = 210**（frozen 6 + docs_long_val 204）。frozen だけでは n=6 で測れないため
  長文 val を合わせます（どちらも val 文書、doc_id の重複 0）。
- **M3**: 位置依存 S 属性の正解率。day3 の分類で held-out の位置依存 S 属性は
  `ends_with_question` だけです（`includes_greeting` は学習・評価データに存在しない）。
  frozen yardstick の `ends_with_question`（**n = 3,348**）の正解率（閾値 0.5）。
  - 参考（ゲートに使わない）: `uses_bullet_points`（day3 で「構造依存、`ends_with_question` と同型」、
    v4 held-out、n = 1,966）の正解率、M2 帯の `ends_with_question`（n = 72）。
- **ガードレール**: `data/val_v2.jsonl` を `sokudan.train.loop.evaluate`（各 run のレポートを

- n < 30 のカテゴリは参考扱い（ゲートに使わない）。上の M1/M2/M3 はすべて n ≥ 30。

## 3. ゲート（数値は §4 の v0.1 実測から機械的に決まる）

**前進ゲート（新 seed 0 の 1 本で判定）** — 次の 3 つをすべて満たせば PASS:

2. **M1** の新 3 シード平均 ≥ v0.1 の最小値
3. **ガードレール**の新 3 シード平均がすべて v0.1 の最悪値以上（RPS は最大値以下）

比較は小数第 4 位で丸めず、スクリプトの出力（倍精度）で行います。

## 5. 学習の手順と停止条件

- 学習: v0.1 seed 0 と同一（`--train data/train_v2b.jsonl --val data/val_v2.jsonl --encoding joint
  --epochs 2 --batch-size 24 --lr 2e-5 --head-lr 2e-4 --seed 0 --save`）で、
  `--local-attention 1024` だけを加える。VRAM 上限は前回までと同じ
  `--max-vram-fraction 0.88` と `PYTORCH_CUDA_ALLOC_CONF=garbage_collection_threshold:0.8,max_split_size_mb:256`。
- 速度の停止条件: 最初の 50 ステップの所要秒を、**同じコマンドから `--local-attention` を外して
  今日この機械で測った 50 ステップ**と比べ、2 倍を超えたら停止（ページングを疑う）。
  v0.1 の記録（659 秒 / 5,618 ステップ）は学習全体の平均なので参考として併記します。
  2 倍超の場合は batch 12 + 勾配累積 2 で 1 回だけ再試行（**現行の `train.py` に勾配累積は
  無いため、その場合は追加実装が必要で、それも記録する**）。それでも 2 倍超なら終了処理。
- PASS なら残り時間 > seed0 学習時間 × 1.3 + 評価時間のときだけ seed 1 / 2。
  FAIL なら追加学習はしない（256 / 512 の試行、ハイパーパラメータ調整もしない）。

## 9. 解釈の注記（2026-09-24、結果の後に追記。§1〜§5 は変更していない）

窓を広げて微調整するだけでは改善せず、悪化しました。ローカル（sliding）層は事前学習で
相対距離 ±64 までしか見ておらず（§1.2: `local_attention` 128 = ±64）、窓 1024 はその層に
事前学習で見ていない距離での RoPE（base 10,000）を使わせる、つまり訓練外の距離への外挿を伴います。

したがって、この結果は **「mask と情報の距離が弱さの原因」という仮説の反証ではなく、
介入手段（窓を広げること）の失敗**として扱います。§7 の FAIL 判定そのものは変わりません。
仮説自体の検証は、アーキテクチャに触れずに入力ブロックの順序だけを変える実験
（`docs/input_order.md`）に引き継ぎます。
