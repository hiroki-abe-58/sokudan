# 入力順の入れ替え実験（事前登録）

**仮説**: v0.1 で位置依存の属性が弱いのは、mask（選択肢マーカー）と、答えを決める state 内の
位置との距離が遠いから。

前回の窓 1024（`docs/local_attention_1024.md`）は、sliding 層に事前学習で見ていない相対距離を
使わせたため、仮説を検証する前に介入手段そのものが壊れました（同 §9）。今回は
**アーキテクチャに一切触れず**（`local_attention` は事前学習の 128 のまま、`--local-attention` は
使わない）、入力ブロックの順序だけを変えます。

- v0.1（`question_first`）: `<s>` 指示 `</s><s>` 選択肢+`<mask>` `</s><s>` **state** `</s>`
- 今回（`state_first`）: `<s>` **state** `</s><s>` 指示 `</s><s>` 選択肢+`<mask>` `</s>`

`state_first` では mask が **state の末尾**に近づき、**state の冒頭**から遠ざかります。
距離仮説が正しければ、末尾で決まる `ends_with_question`（M3）が上がり、冒頭で決まる
`includes_greeting`（M4）が下がるはずです。

**§1〜§5 は新しいモデルの数字を見る前に書き、学習前に commit しています。以後動かしません。**
結果は §6 以降に追記します。

## 1. 実装と前提の確認（Phase 1、測定済み）

### 1.1 現行の入力構築（変更前、commit 709abea の `sokudan/encoding/question.py:encode_joint`）

- **並び**: `prefix` + 指示 + `separator` + （選択肢テキスト + `<mask>`）× 選択肢数 + `separator` + state + `suffix`。
- **特殊トークン**: `SpecialTokenLayout.from_tokenizer` がトークナイザ自身の出力から読み取る。
  ModernBERT-Ja では `prefix` = `<s>`、`separator` = `</s><s>`、`suffix` = `</s>`。
  BERT の `[CLS]` / `[SEP]` に当たるものはこの 3 つ。
- **mask 位置の取得**: 固定オフセットではありません。系列を組み立てながら、`<mask>` を
  追加する直前の長さを `marker_positions` に記録しています。choice / score / bool の 3 種とも同じ
  経路で、モデル（`SokudanJointModel.forward` → `DecisionHead.gather_markers`）はこの位置で
  隠れ状態を取り出し、`marker_mask` で有効な選択肢だけを数えます。
- **切り詰め**: 上限 `MAX_JOINT_TOKENS` = 1024。質問ブロックは切らず（入り切らなければ例外）、
  **state の末尾側**を切ります。

### 1.2 変更点

- `encode_joint(..., input_order="question_first")` に分岐を 1 つだけ追加（`INPUT_ORDERS`）。
  質問ブロック（指示・区切り・選択肢・`<mask>`）と state を同じ部品から組み立て、並べる順序だけを
  変えます。mask 位置は質問ブロック内のオフセット + 質問ブロックの開始位置で求め、返す前に
  全位置が `<mask>` を指すことを検査します。切り詰めはどちらの順でも state の末尾側で、残す
  トークン数も同じです。
- 学習と評価は同じ `encode_joint` を通ります（`JointCollator(input_order=...)`、
  `TrainConfig.input_order`、`build_collator`）。`predict.py` も同じ関数です。
- `scripts/train.py --input-order {question_first,state_first}`（既定 `question_first`）。
  モデル（`SokudanJointModel.input_order`）とチェックポイントの config に保存し、
  `load_checkpoint` / `predict.py` が復元。キーの無い既存チェックポイントは `question_first`。
- `run_model` はバッチの順序とモデルの順序が違えば例外を出します（黙って違う並びで採点しない）。
  評価スクリプトはすべてモデルの順序から collator を作るよう修正。

## 2. 指標（M1〜M3 は `docs/local_attention_1024.md` §2 とまったく同じ）

すべて `scripts/eval_local_attention.py` で計算します（M4 を追加、M1〜M3 の計算は変更なし）。

- **M1**: held-out bool AUROC（frozen yardstick 全体、n = 9,850）
- **M2**: state 400–799 トークン帯の held-out bool AUROC（frozen + `docs_long_val`、n = 210）
- **M3**: `ends_with_question` の正解率（frozen、n = 3,348）。AUROC も記録するが判定は正解率
- **M4**: state の冒頭で決まる表層属性の正解率
  - **選定**: day3 の追加 S 属性（`docs/day3_attribute_expansion.md` の S 段、
    `sokudan/data/intent_attributes.py` の `_SURFACE_V2`）のうち、定義が state の冒頭で決まるのは
    **`includes_greeting` だけ**です。定義は「本題の前に時候または定型の挨拶を一文置く / 挨拶を
    置かず最初の一文から本題に入る」、質問は「冒頭に挨拶があるか」等で、`POSITIONAL_ATTRIBUTES`
    にも「the opening line」として登録されています。他の S 属性（箇条書き、時刻、場所など）は
    本文のどこにあっても決まるので除外。`ends_with_question` は末尾なので M3。
  - **データ**: `includes_greeting` は held-out 5 属性にも v4 held-out にも、v0.1 の学習データにも
    ありません。v4 / v5 の文書コーパス `data/docs_all_v5.jsonl` の **val 分割の文書**から、学習と
    同じ棄却規則（検算器の判定がラベルと一致したものだけ）で 1 文書 1 行・標準の質問形で作ります。
    **n = 70**（true 32 / false 38）。v0.1 も今回の 3 本も、この属性では学習していません。
  - n ≥ 30 なので M4 は判定に使います。
- **ガードレール**: `data/val_v2.jsonl` の choice acc、score RPS、score acc、bool acc（前回と同じ）。

## 4. 判定規則（数値は §3 から機械的に決まる。判定は `runs/io/eval_v01.json` の倍精度値で行う）

1. **破損停止**（seed 0 の評価後）: seed 0 の M1 < **0.854142**
   （= v0.1 最小 0.881718 − 2 × 幅 0.013788）ならモデルが壊れたとみなして停止。M3 の向きも解釈不能とする。
2. **距離仮説が支持される**: 3 シード平均の M3 > **0.679211**（v0.1 最大）、**かつ**
   3 シード平均の M4 < **0.514286**（v0.1 最小）。
3. **距離仮説が棄却される**: 3 シード平均の M3 ≤ **0.679211**。
4. **部分的**: 上のどれでもない場合（M3 平均 > 0.679211 だが M4 平均 ≥ 0.514286 など）。解釈はユーザーに委ねる。
5. **採用候補**（仮説判定とは別）: （M2 平均 > **0.857117** または M3 平均 > **0.679211**）かつ
   M1 平均 ≥ **0.881718** かつ choice acc 平均 ≥ **0.700911**、score RPS 平均 ≤ **0.187460**、
   score acc 平均 ≥ **0.512931**、bool acc 平均 ≥ **0.929407**。該当しても bench は実行しない。
6. 破損停止に当たらない限り、3 シードすべて学習する。

- v0.1 と同一: `--train data/train_v2b.jsonl --val data/val_v2.jsonl --encoding joint --epochs 2
